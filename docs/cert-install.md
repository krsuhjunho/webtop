# 클라이언트에 루트 CA 와 인증서 설치

기기가 서버를 신뢰하고 mTLS 클라이언트 인증서를 내려주려면 **루트 CA 를 먼저** 설치하고, 그 다음 **클라이언트 `.p12`** 를 설치합니다. 등록 페이지(`/enroll/<토큰>`)와 관리 페이지(`/admin/`)에서 CA 파일과 지문을 받습니다.

설치하는 파일은 CA **인증서**뿐입니다. `ca.key` 는 서버에만 있고 어떤 기기에도 복사하지 않습니다.

## 지문 확인

다운로드 전후에 페이지의 지문과 기기가 보여주는 지문을 비교합니다. 한 글자라도 다르면 설치하지 말고 파일을 지웁니다.

- SHA-256 을 우선 비교합니다.
- Windows 인증서 창과 iOS 프로파일 상세는 SHA-1 을 보여 주는 경우가 많습니다. 페이지의 SHA-1 과 비교합니다.

서버에서 같은 값을 확인하려면:

```bash
openssl x509 -in deploy/certs/ca/ca.crt -noout -fingerprint -sha256
openssl x509 -in deploy/certs/ca/ca.crt -noout -fingerprint -sha1
```

`.cer` 는 DER 이고 Windows, Android, iOS 에서 다루기 쉽습니다. `.crt` 는 PEM 이며 Linux 의 `update-ca-certificates` 와 NSS 에 맞습니다. 내용은 같은 인증서입니다.

## 브라우저가 클라이언트 인증서를 묻지 않을 때

1. 브라우저를 완전히 종료했다가 다시 엽니다. 창만 닫히고 프로세스가 남은 경우가 있습니다.
2. CA 가 신뢰된 루트인지, `.p12` 가 개인(사용자) 저장소에 있는지 확인합니다.
3. SSL 상태를 지웁니다. Windows 는 `inetcpl.cpl` → 내용 → SSL 상태 지우기. Chrome 계열은 사이트 데이터를 지운 뒤 다시 접속합니다.
4. 국가 제한에 걸린 공인 IP 는 인증서 선택 창이 뜨기 전에 연결이 끊깁니다. 사설망은 허용됩니다.

CA 를 교체하면 서버 인증서와 모든 클라이언트 인증서를 다시 발급해야 합니다. 기기에서는 이전 루트와 이전 `.p12` 를 지우고 새 루트부터 다시 설치합니다.

## Windows

1. 페이지에서 `.cer` 를 받습니다. 지문을 비교합니다.
2. `certmgr.msc` 를 엽니다. **신뢰할 수 있는 루트 인증 기관 → 인증서** 에서 우클릭 → 모든 작업 → 가져오기. `.cer` 를 고르고 저장소는 **신뢰할 수 있는 루트 인증 기관** 으로 둡니다. 현재 사용자 저장소면 브라우저에 충분합니다.
3. 보안 경고의 지문(SHA-1)을 페이지와 비교한 뒤 설치합니다.
4. 그 다음 `.p12` 를 더블 클릭합니다. 저장 위치는 현재 사용자, 저장소는 **개인** 입니다. 등록 페이지에 나온 비밀번호를 입력합니다.
5. Edge, Chrome, Brave 는 Windows 인증서 저장소를 사용합니다. 사이트에 들어가면 인증서 선택 창이 뜹니다.
6. Firefox 는 인증서 저장소가 따로입니다. 설정 → 개인 정보 및 보안 → 인증서 → 인증서 보기에서 **인증 기관** 에 CA 를 가져오고(웹 사이트 신뢰), **내 인증서** 에 `.p12` 를 가져옵니다. `about:config` 의 `security.enterprise_roots.enabled` 를 `true` 로 두면 Firefox 가 OS 루트를 신뢰하지만, 클라이언트 인증서는 여전히 Firefox 안에 넣어야 합니다.
7. 제거: `certmgr.msc` 의 신뢰된 루트에서 이 CA 를, 개인 저장소에서 클라이언트 인증서를 삭제합니다. 교체할 때는 둘 다 지운 뒤 새 CA 부터 다시 설치합니다.

## macOS

1. `.cer` 또는 `.crt` 를 받습니다. 지문을 비교합니다.
2. 키체인 접근을 열고 **시스템** 키체인을 선택한 뒤 인증서 파일을 끌어 놓습니다. 관리자 암호가 필요합니다. 인증서를 더블 클릭 → 신뢰 → SSL 을 **항상 신뢰** 로 바꿉니다. 지문이 페이지와 같은지 이 창에서 다시 봅니다.
3. 그 다음 `.p12` 를 더블 클릭해 **로그인** 키체인에 넣습니다. 등록 페이지의 비밀번호를 입력합니다.
4. Safari, Chrome, Brave 는 키체인을 사용합니다. 사이트에 접속하면 사용할 클라이언트 인증서를 고르는 창이 뜹니다.
5. Firefox 는 자체 저장소입니다. 설정 → 개인 정보 및 보안 → 인증서에서 CA 와 `.p12` 를 각각 가져옵니다.
6. 제거: 키체인 접근에서 해당 CA(시스템)와 개인 인증서(로그인)를 삭제합니다. 새 CA 는 다시 시스템 키체인에 넣고 항상 신뢰로 설정합니다.

## iOS / iPadOS

1. Safari 로 등록 페이지를 열고 `.cer` 를 받습니다. 설정 앱에 **프로파일 다운로드됨** 이 나타나면 들어가 설치합니다. 지문을 페이지와 비교합니다.
2. 그 다음 **설정 → 일반 → 정보 → 인증서 신뢰 설정** 에서 이 루트의 **전체 신뢰** 를 켭니다. 여기의 지문도 비교합니다. 이 스위치를 켜야 Safari 가 서버를 신뢰합니다.
3. 같은 페이지에서 `.p12` 를 받아 프로파일로 설치합니다. 비밀번호는 등록 페이지에 표시된 값입니다.
4. Safari 가 사이트에서 클라이언트 인증서를 묻습니다. iOS 의 Chrome 도 WebKit 을 쓰므로 같은 프로파일을 사용합니다.
5. 창이 안 뜨면 Safari 를 앱 전환 화면에서 완전히 닫고, 프로파일 설치와 전체 신뢰가 켜져 있는지 확인한 뒤 다시 엽니다.
6. 제거: **설정 → 일반 → VPN 및 기기 관리** 에서 CA 프로파일과 `.p12` 프로파일을 삭제합니다. 전체 신뢰도 함께 사라집니다. 교체하면 새 프로파일을 설치하고 전체 신뢰를 다시 켭니다.

## Android

메뉴 이름은 제조사와 버전에 따라 다릅니다. 보통 **설정 → 보안 → 암호화 및 사용자 인증 정보 → 인증서 설치** 이고, **설정 → 보안 및 개인정보 보호 → 기타 보안 설정 → 인증서 설치** 인 기기도 있습니다.

1. **CA 인증서** 를 고르고 `.cer` 를 설치합니다. 화면에 나온 지문을 페이지와 비교합니다. 이 인증서는 사용자 CA 로 들어갑니다.
2. Chrome 과 Brave 는 사용자 CA 를 신뢰합니다. 모든 앱이 그렇지는 않습니다. 일부 앱은 시스템 CA 만 신뢰하므로 이 루트로는 그 앱의 서버 검증이 되지 않을 수 있습니다.
3. 그 다음 같은 메뉴에서 **VPN 및 앱 사용자 인증서** 로 `.p12` 를 설치합니다. 비밀번호를 입력합니다.
4. Chrome 또는 Brave 로 접속하면 클라이언트 인증서 선택 창이 뜹니다.
5. 창이 안 뜨면 브라우저를 강제 종료하고, 사용자 인증 정보에 인증서가 있는지 확인한 뒤 사이트 데이터를 지우고 다시 엽니다.
6. 제거: **사용자 인증 정보** 에서 이 CA 와 사용자 인증서를 각각 삭제합니다. 교체하면 CA 와 `.p12` 를 순서대로 다시 설치합니다.

## Linux

시스템 저장소와 브라우저 저장소는 따로입니다.

1. PEM `.crt` 를 받습니다. 지문을 비교합니다.

   ```bash
   openssl x509 -in ~/Downloads/webtop-ca.crt -noout -fingerprint -sha256
   sudo cp ~/Downloads/webtop-ca.crt /usr/local/share/ca-certificates/webtop-ca.crt
   sudo update-ca-certificates
   ```

   Ubuntu 와 이 명령을 쓰는 배포판의 curl, 시스템 도구가 루트를 신뢰합니다. 파일 이름은 `.crt` 여야 합니다.

2. Chrome 과 Brave 는 NSS 를 사용합니다. `libnss3-tools` 의 `certutil`, `pk12util` 이 필요합니다.

   ```bash
   mkdir -p "$HOME/.pki/nssdb"
   certutil -d "sql:$HOME/.pki/nssdb" -N --empty-password
   certutil -d "sql:$HOME/.pki/nssdb" -A -n "Webtop CA" -t "C,," -i ~/Downloads/webtop-ca.crt
   pk12util -d "sql:$HOME/.pki/nssdb" -i ~/Downloads/client.p12
   ```

   데이터베이스가 이미 있으면 `-N` 은 생략합니다. `-t "C,,"` 는 이 CA 를 SSL 신뢰 앵커로 표시합니다. `.p12` 비밀번호를 묻습니다.

3. Firefox 는 프로필마다 NSS 데이터베이스가 따로입니다. 설정 → 개인 정보 및 보안 → 인증서에서 CA 와 `.p12` 를 가져오거나, 프로필의 `cert9.db` 가 있는 디렉터리에 같은 `certutil` / `pk12util` 명령을 실행합니다. 시스템 저장소나 `~/.pki/nssdb` 만으로는 Firefox 에 들어가지 않습니다.
4. 선택 창이 안 뜨면 브라우저를 완전히 종료했다가 다시 열고, `certutil -d "sql:$HOME/.pki/nssdb" -L` 로 CA(`C,,`)와 클라이언트 인증서가 보이는지 확인합니다.
5. 제거:

   ```bash
   sudo rm -f /usr/local/share/ca-certificates/webtop-ca.crt
   sudo update-ca-certificates --fresh
   certutil -d "sql:$HOME/.pki/nssdb" -D -n "Webtop CA"
   ```

   클라이언트 인증서의 닉네임도 `certutil -L` 로 확인한 뒤 `-D` 로 지웁니다. Firefox 프로필에 넣은 인증서는 그 프로필에서 지웁니다. 교체하면 새 CA 를 시스템과 NSS 에 다시 넣고 `.p12` 를 다시 가져옵니다.
